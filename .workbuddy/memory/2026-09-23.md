### 新增文件
- `scripts/gen_research_prompts.py` — 从 catalog.yaml 生成 11 份定制 prompt + 答案脚手架。
  prompt 会自动带上「我已经知道/已经试过」段（读 catalog 的 notes/streak/daily_amount），
  并注入本机客户端路径（`apps.find_exe`）。`--force` 重建；**答案文件已存在则永不覆盖**。
- `scripts/check_research_answers.py` — 入库前校验：区分 待填/已填/空/有风险，
  扫 JWT / Bearer / `sk-` / Authorization / 长 base64(40+) / 口令 / cookie 字段，
  命中 exit 1。已用一条伪造 JWT 实测触发成功。
- `research/README.md` — 流程 + 目录 + 回填规矩 + 优先级
- `research/ANSWER-SCHEMA.md` — 独立答案格式（生成器每次重写，保持同步）
- `research/prompts/<id>.md`（11 份）、`research/answers/<id>.md`（11 份脚手架）
- `skill/SKILL.md` 增加「补齐自动化路线」一节

### 答案 schema 五段
`checkin` / `status` / `automation` / `evidence` / `open_questions` / `catalog_patch`。
`catalog_patch` 是能直接合入 catalog.yaml 的片段。

### 关键设计决定
- **`status_command` 是预留字段**，语义：输出一行 JSON `{"balance": n, "claimed_today": bool}`，
  供后续 `credit sync` 拉真实余额校正台账。当前运行时只消费 `claim_mode` 和 `command`，
  多填不影响现有逻辑（yaml_lite 是通用解析器，未知 key 无害）。
- prompt 里的硬约束明确禁止：解密登录态、输出 token 原文（一律 `<redacted>`）、
  上传本机数据、替用户执行领取/兑换/抽奖。签到**只给方法，不让对方代点**。
- 调研优先级：minimax > autoclaw > traework > lobsterai > workbuddy > dumate/todesk >

## MiniMax 端点逆向成功（提交 d78f245）

用户质疑「模拟点击被 isTrusted 过滤」的结论 —— **质疑成立**。

### isTrusted 结论修正（重要）
- `scripts/ui_claim.ps1` 用 UIA `InvokePattern.Invoke()` → 脚本层派发 → `isTrusted:false` → **会被过滤，成立**
- `ui_claim_minimax.ps1` / `ui_claim_autoclaw.ps1` 用 `SetCursorPos` + `mouse_event` → OS 级输入注入 → **isTrusted:true，不受影响**
- MiniMax 失败的真正原因是脚本 bug：
  1. 点的是「今天」标签（y≈1629），真正按钮是「签到得@400」（y≈1882）
  2. 校验窗口是「标题锚点 y≈1509 ±200」= 1309~1709，**按钮 1882 根本不在窗口内**
  → 已修：点击目标改为匹配 `签到得|领取|领积分|签到领`，校验窗口基准改为按钮位置 ±300

### 端点（从 app.asar 逆向，527MB Electron 归档）
- `GET  https://agent.minimax.cn/minimax-cloud/api/v1/signin/status`
- `POST https://agent.minimax.cn/minimax-cloud/api/v1/signin/claim`
- 鉴权：`Authorization: Bearer`（不进查询串）、`user_id` 查询参数、仅 HTTPS
- **阻塞点**：渲染进程走 `app://cloud` 自定义协议，鉴权头由**主进程**注入，
  且只放行 `/minimax-cloud/api` 前缀 → 外部 CLI 直连需自备 token
- 数据模型 `@mavis/shared/src/daily-signin.ts`：
  `SigninDayStatus 1=Upcoming 2=Claimable 3=Claimed 4=Disabled`、
  `SigninClaimResult 1=Claimed 2=AlreadyClaimed`、`day_no ∈ 1..7`

### app.asar 归档格式（可复用）
`u32@0=4`；`u32@12=json_len`；JSON 头从 offset 16 起；body 起始 = `(16+json_len)` 上对齐 4 字节。
（第一次按 `u32@4` 读 pickle_size 会失败。）
