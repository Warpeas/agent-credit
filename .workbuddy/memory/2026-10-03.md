## 01:05 minimax 掉登录：根因是 loginEpoch，已修复

主人反馈「脚本 external 签完，我再打开客户端就退回需要登录」。

**根因**：脚本 OAuth2 刷新后写回 `auth.json` 时只改了
`accessToken / refreshToken / tokenType / expiresAtMs / generation`，**没动 `loginEpoch`**。
客户端启动时发现 token 与 loginEpoch 不匹配 → 判定会话失效 → 退回未登录。

| | loginEpoch |
|---|---|
| 刷新前（备份 auth.json.bak.20261002） | `ce652e36-707c-4973-a193-1befb828129a` |
| 现在（00:19:58，主人重新登录后） | `5aea2b3f-030d-42af-b068-6fbeb9cc5c09` |

**修复**：`vendor/minimax-auto-signin/signin.py` 加 `ALLOW_TOKEN_REFRESH` 开关，**默认关闭**
（设 `MINIMAX_ALLOW_TOKEN_REFRESH=1` 才开）。关闭时：
- `refresh_token()` 直接返回当前 token，不刷新、不写文件
- 401/403 不再强制刷新重试
- token 失效时打印明确提示（让客户端跑一次自己续期 / 走 UI），退出 2

实测：签到正常（`[granted] 3000`），且 auth.json **完全未被触碰**
（gen 仍 57、loginEpoch 不变、mtime 仍是 00:19:58）。

⚠️ 教训：动第三方客户端的凭据文件，必须同时看**有没有会话级标识**（loginEpoch / session id /
device id 之类）。只轮换 token 不换会话标识 = 人为制造不一致。
