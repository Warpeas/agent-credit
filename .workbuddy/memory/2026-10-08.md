## LobsterAI：4 个 bug + 1 次自造成本

### 修的 bug（`scripts/ui_claim_lobsterai.ps1`）

1. **`$exe` 路径错**：写成 `'$env:APPDATA\AppData\Local\Programs\...'`，
   APPDATA 后面又拼 `AppData\Local`，拼出 `...\Roaming\AppData\Local\...` 不存在。
   → `Join-Path $env:LOCALAPPDATA 'Programs\LobsterAI\LobsterAI.exe'`。
   **这个 bug 潜伏很久**：10-07 能跑是因为实例被别的脚本先拉起，走 existing window 分支，
   从没验证过 `$exe`。凡是"以前能跑现在不行"，先怀疑那条没被走到的分支。
2. **`Restore-Scene` 未定义**：启动流程 ~128/~142 行调用它，函数定义在 ~279 行。
   PowerShell 顺序执行 → `无法将"Restore-Scene"项识别为 cmdlet`。
   → 把 Save/Restore-Foreground + Close-LaunchedApp + Restore-Scene 整组上移到启动流程之前。
3. **`$shotPath`/`$ocrPath`/`$frameDir` 单引号**：`$root` 不展开，实际是字面量
   `$root\logs\...` → `GDI+ 中发生一般性错误`，OCR 链路崩在第一张截图。
   → 改`Join-Path $root`。
   ⚠️ **同类 bug 三处同源**：单引号里的 `$` 一律不展开。凡 `$var='...\...'`
   立刻可疑，不管写成 `$root` 还是 `$env:X`。
4. **重复 `$script:LaunchedByUs = $false`**：第二处位于启动流程之后，
   会把刚置的 `true` 冲回去 →脚本自己拉起的客户端永远不关。

### ⚠️ 我造成的损失：把登录态点没了

用户栏选择器原是 `x<15%W 且 y>80%H 取第一条`。面板展开时该区域同时有
「退出登录」(103,1064) 和「我的」(97,1145)，OCR 返回顺序不保证，
break 在「退出登录」上 → 脚本点了退出登录，**`auth_tokens` 从
`%APPDATA%\LobsterAI\lobsterai.sqlite` kv 表消失**，external 脚本跟着报「未登录」。
主人手动重新登录才恢复。

修法（`Find-UserBar` + `Test-PanelOpen`）：
① 黑名单挡 `退出登录|立即登录|登录|token|积分礼|邀请|充值|用量|额度|查看|明细|设置|账号`
② 优先精确命中「我的」③ 面板已展开时**不再点 toggle**（再点会把它关掉）。
实测 22:23 精确命中「我的」@127,1159，登录态 `186****1819` 正常。

**教训：OCR 空间启发式选可点元素时，必须排除同区域的其他可点元素。
`y > 80%H` 这种"最下面那条"的假设在面板展开时不成立——展开态与收起态
的布局完全不同，脚本却共用一套选择器。凡是"toggle 类 UI"，
判"当前是开是关"要单独做，不能只靠点之前的位置假设。**

## TraeWork：缺窗口归位，一直失败的真因

签到锚点在左下角，正好是挂在屏幕外的那部分 → OCR 看得见工作区、
永远看不见签到入口。补上后 dry-run 立刻从"未找到签到入口"
变成"将点击签到入口: 每日领 @64,482"，真实点击返回
「本账号今日已签到，明日冉来」。

⚠️ **`Cap32` 里`SetWindowPos` / `GetSystemMetrics` 也原本没声明** ——
新加代码调它们必须同时补 P/Invoke，否则运行即崩。

## 新增：非提权计划任务启动器（沙箱拉不起 GUI 的通用解法）

沙箱会话里 `Start-Process` 拉 GUI 客户端进程数恒为 0。
`RunLevel=Limited` + `LogonType=Interactive` 的计划任务可以在真实桌面会话里拉起。
不弹 UAC。

- `scripts/_task_lobsterai.ps1 -Mode claim|verify` — 拉起并跑 LobsterAI
- `scripts/_task_traework.ps1 -ProcessName <name> [-WaitReady]` — 只拉起客户端
- `scripts/_task_traework_claim.ps1 -Mode claim|dry-run|explore` — 跑 TraeWork

**UIPI 复核**：TraeWork 旧文档说"必须提权，否则点击被 UIPI 丢弃"。
实测客户端既然是 Limited 任务拉起的（中完整性），签到脚本同完整性跑，
点击**正常生效**，不需要 UAC。UIPI 只拦 LOW→HIGH，两边同级不受影响。

⚠️ 拉起客户端的任务**跑完不要Unregister** —— 任务生命周期 = 应用生命周期，
Stop/Unregister 会连带杀掉客户端。实测踩过：claim 跑完自动关客户端，
下一轮直接 notfound，得重新拉。
