## MonkeyCode 今日根因：截图抓到了别人的窗口（不是缩放、不是坐标）

晚上补跑时逐层剥开，**今天所有关于「webview 没渲染」的描述都是症状不是根因**：

1. 跑 `credit.py checkin --only monkeycode_credit` 报 **「无 UI 配方」**——
   因为 `monkeycode_credit` 走的是 `command:`（`python scripts/ui_claim_monkeycode.py`），
   命令失败后会**回落到 UI 路由**，而 UI 路由里没有 MonkeyCode 配方，
   于是**真实失败原因被这句兜底文案盖住**。排查要走命令本身，别信这个提示。
2. 直接跑脚本，日志显示客户端**启动是成功的**（pid 2s 内出现），
   所以「冷启动必失败」这个旧结论对今天不成立。
3. `content_ink` **整整 60 秒恒定 40**、完全不波动 → 不是「渲染慢」，
   是**抓到静态的别人画面**。决定性证据：把现场截图 `_monkey_account.png` 拿去 OCR，
   只认出一行 **`WorkBuddy`**——抓到的是 WorkBuddy 的窗口。
4. 枚举 MonkeyCode 同 pid 全部窗口，**主窗口 `IsWindowVisible=False`**：
   ```
   (2752568, 'MonkeyCode', 'Tauri Window', visible=False, iconic=False,
    cloaked=0, exstyle=0x40110, rect=(490,490,2426,1615))
   foreground: 'WorkBuddy' Chrome_WidgetWin_1
   ```
   **客户端以「只驻留托盘」的方式启动**（tray_icon_app 在、主窗口隐藏）。
   `find_main` 只按 class+标题+面积筛、**没查可见性** → 选中隐藏窗口；
   隐藏窗口上 `SetForegroundWindow` 静默无效，**而且 `GetForegroundWindow()`
   还会返回它**（所以「前台」这个判据会被骗过）。

### 本轮改动（已提交）

- `find_main`：**可见性优先**（area × 10），全不可见时仍返回面积最大者交给上层显示。
- 新增 `ensure_foreground()`：显示(SW_SHOW) → 还原 → Alt 技巧 → 绑输入队列强切。
- 新增 `client_owns_point()`：用 `WindowFromPoint` 校验「窗口中心那一点最上层
  是不是本客户端」——这是「屏幕捕获到底拍到了谁」的直接判据。
- **两道硬闸门**：置前/可见/归属校验不过 → **拒绝任何点击**，报 pending 不入账。
  理由：盲点别人的窗口正是「把登录态点没了」那类事故的成因，宁漏勿险。
  ✅ 实测有效：计划任务那轮 `center_owned_by_client=False`，闸门拦下了，0 次点击。
- `--ink-min` 变成可调参数（`INK_MIN_DEFAULT` 保留 40 但**明确标注这个值不可靠**，
  未标定的原因见下）。
