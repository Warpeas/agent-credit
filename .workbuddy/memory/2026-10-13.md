## Trae 余额 OCR 修复（主人派单，已闭环）

**根因不是正则，是 UI 改版**（2026-10-09 官宣合并后客户端大改）：
账户条从「用户71294228173 免费 3,527」变成「0用户71294228173免费」——**余额没了**，
且整行被 OCR 并成一条、words 是**单字数组**，所以千分位正则恒 -1、按 word 找「用户」的
锚点也全部失效（探索时 `account candidates=0`、`menu_opened=False` 就是这两个）。

**修复（scripts/ui_claim_trae.ps1）**：判据换血，不再依赖余额。
- 新增 `Find-Granted`（主）：正则抓卡片上的「已获得N积分」取**实发额度**；
  `Find-OfferAmount`（校验）「每日领N积分」；`Test-AlreadyCard`（幂等）会员推广态；
  `Find-SignButton`（按钮定位）按 OCR 短文本在入口行下方找「签到」，
  取代「像素扫药丸 + 4 个 offset 轮换」（新布局里药丸扫描会扫到背景深色块 x=664 len=235）。
- 判定优先级：granted → 余额差（备用）→ 文案（兜底，退回 daily_amount）。
- 补了结尾兜底：以前 `if ($bal0 -ge 0)` 才报 pending，现在 bal0 恒 -1，
  判据全落空时脚本会**静默走到文件末尾不写结果文件**，调用方只能干等超时。
- 账户条锚点改为按整行文本（`-match '用户\s*\d+'`）定位。

**防回归**：判据正则集中定义在 ps1 顶部（`$RE_GRANTED` / `$RE_GRANTED2` / `$RE_OFFER` /
`$RE_ALREADY` / `$RE_SIGNBTN`），新增 `scripts/test_trae_states.py`：从 ps1 **源码里抠正则**
（不复制副本，避免两头漂移）跑三态真实样本 + 按钮定位，全绿 exit 0。
