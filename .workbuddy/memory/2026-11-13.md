### Qoder CN：还原后窗口变 12px 细条（已修）

- 证据（`logs/ps1_qodercn.log`）：
  - `00:23:53 restore-rect: now -12,0 12x2076 (expect -12,0 3600x2076)` → RESULT pending
  - `00:29:15` 同款，usage 轮也中招
  - 07:29 那轮同样出现过一次（当时以为是「最大化态下改尺寸被忽略」）
- 机理：`Restore-OriginalRect` 用 `SetWindowPos(...,0x0014)` 传宽高，被 Electron/Chromium 侧丢掉，
  只落了位置；读回校验只是打日志、没有补救 → 窗口留一条 12px 缝。
  下一轮 `Find-QoderWindow` 的「残留条带」判据也拦不住（右边界 0 > vLeft+48+16 不成立），
  反而会把细条当 OriginalRect，永远修不回来。
- 修法（`scripts/ui_claim_qodercn.ps1`）：
  1. `Test-RectClose` + `Set-RestorePlacement`（WINDOWPLACEMENT.rcNormalPosition + SetWindowPlacement）；
  2. 普通态还原改成四步递进、每步读回校验：
     `SetWindowPos` → `SetWindowPlacement(showCmd=1)` → 「先在 0,0 定尺寸再挪位」→ 夹进桌面兜底；
  3. 最大化分支：`SW_MAXIMIZE` 后校验 `IsZoomed`，不成就补 `SetWindowPlacement(showCmd=3)`；
  4. 残留判据新增 `$tooSmall`（W<600 或 H<400）：细条按 `Get-Placement` 的正常 rect 还原，
     没有正常态就 1200x800，绝不原样保留。
- 未做：页面复位（签完仍停在「权益中心」）。需要「记录入口 → 原路返回」，改动面大，留待主人点头。

### MonkeyCode：收尾还原同样加固（已修）

- `restore_rect()` 原来只 `SetWindowPos` 一次、无校验无日志 → 和 Qoder 同款「宽高被丢」的坑完全没有兜底，
  且 `_cleanup` 只在「不是本次拉起」时才还原；本次冷启动的实例是**带着屏外条带直接关掉**的，
  Tauri 会把位置写进自己的状态文件 → 下次可能在屏外开窗（MEMORY 里「防 Electron 持久化屏外位置」就是这条）。
- 修法（`scripts/ui_claim_monkeycode.py`）：

     优先用 `GetWindowPlacement` 的 rcNormalPosition；
  3. `_cleanup` 改成**关窗前一律还原** rect + 最大化态，失败落日志。
- 注意：catalog 里 `--idle-wait 0 --no-idle-gate` **保持不动**。10-25 的结论仍成立：
  客户端一启动就自注入一次输入事件 → per-click 空闲闸门 100% 拒绝点击。别拿掉这个参数。
