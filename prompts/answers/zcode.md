## 补充说明

**指标错配**：维度一/三的「每日免费积分 + 签到脚本 + 改版脆弱性」对 ZCode 不适用。它是订阅制（GLM Coding Plan / BigModel）：账号绑定后额度由服务端自动生效，无签到动作。横向对比建议与 Kimi Work 同归「订阅型」分组，不进每日自动签到盘；台账按 claim_policy=never_auto / claim_mode=never 记录。

**相对亮点**：

- 编码 agentic 全流程 + 子智能体/目标模式/Hooks/定时/闲时任务；本仓库日常维护即由 ZCode 会话完成（可当场复核的实证，不是话术）。
- computer-use 原生桌面操控 + browser-use 浏览器自动化 + MCP/插件/技能生态齐全。
- 非高峰（14:00–18:00 UTC+8 之外）5 折抵扣，长任务放非高峰跑可显著省额度（官方口径：对比按量调用 GLM-5.3 标准 API 最高省 92% 成本）。

**相对短板**：

- 对「签到积分台账」零产粮：没有每日可领额度，进不了自动签到盘。
- 内置只有 GLM 系，无多厂商模型货架；第三方模型接入未确认。
- 无生图/生视频输出端；无独立官方移动客户端（Remote/Bot 远控为主）。

**未确认清单（欢迎主人实测后回填）**：本账号（bigmodel-start-plan）对应套餐档位与实际积分余额；ZCode 是否可接第三方模型端点；浏览器调试深度（console/网络读取）；音频模态；移动端 Remote 的实际体验。
