Agent 评价指标体系

基于 catalog.yaml 现有数据梳理，分为「已有数据」与「待实测」两组。每个指标附评分口径，方便逐项填充。

已有数据（catalog 可提取） 部分有（需补充实测） 待实测（目前空白）

维度一：额度价值（V）— 权重 0.4

回答一个问题：这些积分到底值多少钱、能用多久？现有 V 分是综合判断，下面拆成可独立打分的子项。

1.1 日额度（标准化） 已有数据
指标 每日可获得多少积分/token。token 类需折算（1M token ≈ 多少「有效积分」待定）。 全部有
评分口径 5 = 500+/天 或 10M+ token  |  4 = 200-499/天  |  3 = 100-199/天  |  2 = 20-99/天  |  1 = <20/天 或一次性
1.2 有效期 已有数据
指标 积分领完后保留多少天。当日清零=0，30天可累积远优于当日清零。 全部有
评分口径 5 = 30+天可累积  |  4 = 7-29天  |  3 = 当日清零但有永久托底  |  2 = 当日清零  |  1 = 一次性/过期不续
1.3 连签/额外加成 已有数据
指标 连续签到是否有额外奖励（如第7天+1000）。有连签加成的实际周收益远高于线性日额度。 全部有
评分口径 5 = 7天周期加成 ≥50%  |  4 = 有加成但 <50%  |  3 = 每月登录赠固定额  |  2 = 无加成但额度本身大  |  1 = 无加成且额度小
1.4 实际可消耗性 待实测
指标 领到的积分能不能真正花出去？有些产品额度大但单次任务消耗极高、或模型调用受限，实际用不掉多少。 待实测
评分口径 5 = 日常任务轻松消耗、不浪费  |  4 = 大部分场景够用  |  3 = 偶尔够用、经常花不完  |  2 = 基本花不掉（清零=浪费） |  1 = 完全用不出去

实测方法：连续 3 天正常用，记录每天消耗量 vs 日额度，算消耗率。

维度二：能力覆盖（C）— 权重 0.3

回答：这个 Agent 能帮我做什么？现有 C 分偏主观，下面拆成可独立验证的子能力。

2.1 模型代际 已有数据
指标 提供的模型是哪一代？是否包含当前一线模型（K3/GLM-5/V4/M3 等）。 全部有
评分口径 5 = 多厂商最新旗舰（K3+GLM-5+V4 级） |  4 = 有 1-2 个一线 + 其他  |  3 = 上一代旗舰为主  |  2 = 仅自研/偏旧  |  1 = 模型不明或极旧
2.2 编码能力 待实测
指标 能不能写代码、改 bug、做项目？给一个真实编码任务，看完成度。 待实测
评分口径 5 = 独立完成中型项目、vibe coding 流畅  |  4 = 能写能改、偶尔需要纠正  |  3 = 能写简单脚本、复杂项目吃力  |  2 = 只能补全/小修  |  1 = 编码不可用

实测方法：同一个中等复杂度任务（如「写一个 Python CLI 工具+测试」），各家跑一遍，对比完成度。

维度三：领取可靠性（A）— 权重 0.3

回答：签到能不能稳定跑通、不靠人盯着？这部分数据最完整。

3.1 领取方式 已有数据
指标 external 直签 > UI 自动化 > 手动签到 > 不自动。越自动越可靠。 全部有
评分口径 5 = external 直签（零 GUI） |  4 = UI 全自动且稳定 |  3 = UI 自动但偶发失败 |  2 = 需手动触发 |  1 = 不自动
3.2 自动化稳定性 待实测
指标 过去 30 天签到成功率。UI 路线改版就挂、external 几乎不掉。 部分有
评分口径 5 = 30 天 100% 成功 |  4 = ≥90% |  3 = ≥70% |  2 = ≥50% |  1 = <50% 或从未自动过

实测方法：看 logs/checkin_*.log 统计 30 天 ok/already vs pending/fail 比例。

3.3 脆弱性（改版风险） 待实测
指标 客户端改版后签到会不会挂？external 几乎免疫，UI OCR 路线一改版就废。 部分有
评分口径 5 = external 直签，改版免疫 |  4 = UI 锚点健壮、改版后易修 |  3 = 偶需调整 |  2 = 经常因改版失效 |  1 = 每次改版必挂

维度四：实际体验（主观评分，不纳入综合分）

这些指标不影响 V/C/A 综合分，但对「今天用哪个」的决策很关键。全部待实测。

4.1 响应速度 待实测
指标 从发出指令到开始输出的延迟，以及流式输出的吞吐。 待实测
评分口径 5 = 秒回、流式飞快 |  4 = 1-3s 起、流畅 |  3 = 3-8s 起、可接受 |  2 = 8-15s 起、偶尔卡 |  1 = 经常超 15s 或卡死
4.2 指令遵循 待实测
指标 能不能听懂人话？给复杂指令时是否抓得住重点、不跑偏。 待实测
评分口径 5 = 复杂指令一次到位 |  4 = 偶尔需补充说明 |  3 = 经常抓不住重点 |  2 = 需反复纠正 |  1 = 基本听不懂
4.3 上下文管理 待实测
指标 长对话中是否丢失早期上下文，多轮迭代是否稳定。 待实测
评分口径 5 = 长对话不丢、多轮稳定 |  4 = 偶尔需要提醒 |  3 = 10+ 轮后开始忘 |  2 = 5 轮后就丢 |  1 = 几乎没有上下文
4.4 工具/MCP 生态 待实测
指标 支持多少工具/插件/MCP？能否自定义扩展？生态丰富度。 待实测
评分口径 5 = MCP + 丰富插件市场 |  4 = MCP 或自有插件体系 |  3 = 有限工具支持 |  2 = 仅内置工具 |  1 = 无扩展能力

实测优先级建议

优先测 S/B 档的「待实测」指标——它们是你真正会用的，评分细化有实际决策价值。C/D 档大多「不自动」，除非发现惊喜否则不值得花时间测。
第一批：高优先级（日常在用的）
Agent待测指标建议任务
MiniMax浏览器操控、电脑操控、多模态给一个需要打开网页填表的任务
WorkBuddy编码能力、响应速度、指令遵循同一个编码任务跑一遍
Qoder CN响应速度、指令遵循、上下文长对话 10+ 轮看丢不丢
Trae浏览器操控、编码能力对比 WorkBuddy 同一任务
第二批：中优先级（偶尔用的）
Agent待测指标建议任务
AutoClaw浏览器操控、电脑操控试一个本地文件操作任务
Loomy浏览器操控、电脑操控、移动端同步手机端创建一个任务看桌面端能否看到
DuMate浏览器操控、编码能力搜索+文档任务
Mavis浏览器操控、电脑操控试电脑管理场景
第三批：低优先级（备用/清零档）
Agent待测指标建议任务
LobsterAI编码能力（BYOK 场景）接 Claude/GPT 后跑同一任务
扣子 Coze多模态、工具生态试 Seedream 生图
